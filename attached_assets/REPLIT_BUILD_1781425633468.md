# Prayag Production Planning — Replit Build Pack (Master)

This single file contains everything Replit's Agent needs to build the app:
setup, the master prompt, phase prompts, the post‑fetch sanity check, model
tiering, secrets, and the source file‑IDs. Attach `PP_schema.sql`,
`Prayag_PP_Google_Sheets_FileIDs.xlsx`, and (optionally) the Architecture doc
to the first Agent message.

Requirements captured:
- Division dropdown (PTMT / CP) on every screen.
- Buffer **multiplier is a user input** (never hard‑coded); single, or MIN/MAX pair, or per‑category overrides.
- Data fetched by the **Replit Google connector** (read‑only) by file ID.
- After every fetch, data is **sent to Claude for a sanity check** (catch missed/wrong/partial fetches). Claude assesses only — never edits numbers.
- **Logic runs deterministically on Replit** (not Claude); identical numbers regardless of any model.
- **Excel export** of plans; **Claude‑written notes/summary downloadable as PDF**.
- **PostgreSQL** is the single source of truth with **no data duplication** (natural keys + upsert + batch hash).
- **Legacy data imported once** (guarded by an import ledger).
- **Model tiering**: fast model for daily/weekly narrative, deep model for monthly/quarterly/board narrative. **The sanity check always uses the deep model regardless of cadence.**

## PART D — The selectModel helper (single source of truth)

```javascript
// models.js — the ONLY place an Anthropic model is chosen
const FAST = process.env.ANTHROPIC_MODEL_FAST || 'claude-sonnet-4-6';
const DEEP = process.env.ANTHROPIC_MODEL_DEEP || 'claude-opus-4-8';
const MAX_FAST = parseInt(process.env.MAX_TOKENS_FAST || '1500', 10);
const MAX_DEEP = parseInt(process.env.MAX_TOKENS_DEEP || '4000', 10);
const DEEP_PERIODS = new Set(['monthly', 'quarterly', 'fiscal_year']);

function selectModel(periodType, { override = null, board = false } = {}) {
  let tier;
  if (override === true) tier = 'deep';          // sanity check passes this
  else if (override === false) tier = 'fast';
  else if (board || DEEP_PERIODS.has((periodType || '').toLowerCase())) tier = 'deep';
  else tier = 'fast';
  return tier === 'deep'
    ? { model: DEEP, maxTokens: MAX_DEEP, tier }
    : { model: FAST, maxTokens: MAX_FAST, tier };
}

// usage — narrative writer (follows cadence):
//   const { model, maxTokens, tier } = selectModel(periodType,
//          { override: deepFlag, board: isBoardReport });
// usage — sanity check (always deep):
//   const sc = selectModel(periodType, { override: true });

module.exports = { selectModel };
```

Fallback wrapper (retry once on FAST if DEEP errors, log the downgrade):
```javascript
async function callWithFallback(client, sel, payload, recordDowngrade) {
  try {
    return await client.messages.create({ model: sel.model, max_tokens: sel.maxTokens, ...payload });
  } catch (e) {
    if (sel.tier === 'deep') {
      recordDowngrade && recordDowngrade(sel.model);              // log it on the artefact
      const fb = { model: process.env.ANTHROPIC_MODEL_FAST || 'claude-sonnet-4-6',
                   max_tokens: parseInt(process.env.MAX_TOKENS_FAST || '1500', 10) };
      return await client.messages.create({ ...fb, ...payload });
    }
    throw e;
  }
}
```

## PART F — Acceptance criteria

**Data & engine**
- Re-pulling the same month updates rows in place (no duplicates); an identical batch is skipped as 'no change'.
- The multiplier is taken from the run (never hard-coded); the plan_run stores the multiplier(s) used and is reproducible.
- Legacy import refuses to run a scope twice.

**Sanity check**
- An empty/partial pull, wrong-month, wrong-file, or shifted column is caught and HOLDS the batch with a named Re-fetch action.
- The sanity-check Claude call runs on the **deep** model even for a daily/weekly pull (recorded `tier='deep'`), while that run's report narrative may be fast.
- Claude's findings are stored and shown; no data values are altered by the check.

**Tiering**
- Daily/weekly narrative uses `ANTHROPIC_MODEL_FAST`; monthly/quarterly/board narrative uses `ANTHROPIC_MODEL_DEEP` — verifiable from recorded `model`/`tier`.
- "Deep analysis" override forces deep on a fast period and vice-versa (narrative only).
- Changing the Secrets swaps models with no code change.
- Identical input data yields identical numeric tables on both tiers (only prose differs).
- If the deep model errors, the run completes on the fast model and the downgrade is logged.
