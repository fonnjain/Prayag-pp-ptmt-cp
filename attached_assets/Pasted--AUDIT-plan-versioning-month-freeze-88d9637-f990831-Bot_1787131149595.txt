## 1. The close boundary is the 8th, not the 7th — confirm this is intended

`plant-lifecycle.ts`:

```typescript
const closedAt = `${nextMonth(month)}-08T00:00:00.000Z`;
const isGrace  = month === previousMonth(currentMonth) && now.getUTCDate() <= 7;
```

So July is in GRACE through 7 August inclusive and CLOSED from the 8th. The test name states it plainly: *"grace through the 7th and close on the 8th"*.

Your instruction was *"once a month ends, in the subsequent month **on the 7th**, that should close the data"* — which reads as closing **on** the 7th. The implementation gives one extra day.

Internally consistent either way, so this is a business call, not a bug — but it should be your call, not a default. If closing on the 7th is what you meant, change `<= 7` to `< 7` and `-08` to `-07`, and update the test name.

## 3. `fetchMonthlyTargets` still falls through to a live rebuild for future months

`plant-ingestion.ts:141–162`:

```typescript
const timeline = await getPlanVersionTimeline(month, "PTMT");
const latest = timeline.at(-1);

if (month >= currentMonthStr()) {
  const planItems = await buildPlanItems(month);   // ← still reachable for a FUTURE month
```

The `>=` is unchanged, so a future month with an empty timeline still rebuilds from current uploads. The test *"future monitoring returns a named no-plan state without rebuilding targets"* passes because `plant-monitoring.ts` guards on lifecycle state **before** reaching here — but the guard lives at the caller, not at the function.

`fetchMonthlyTargets` is exported and callable from anywhere. Worth adding the guard inside it too:

```typescript
if (resolvePlantMonthLifecycle(month).state === "future") return [];
```

Defence in depth, one line, and it makes the function safe regardless of who calls it next.

Also note the function returns `timeline.at(-1)` — the **latest** version — which is correct for a whole-month target figure, but it means any consumer of `fetchMonthlyTargets` that isn't going through the timeline-aware path gets latest-version semantics. Worth confirming nothing outside `plant-monitoring.ts` / `plant-engine.ts` relies on it for per-week numbers.
