## ❌ The category guard is wrong, and it is currently breaking production

```typescript
const categoryProducedTotal = [...categoryMap.values()].reduce((sum, d) => sum + d.produced, 0);
if (Math.round(categoryProducedTotal) !== Math.round(plantProduced)) {
  throw new Error(`plant-engine: … pcs plant total is not attributed to categories for ${month}`);
}
```

That invariant cannot hold. `:325–328`:

```typescript
for (const { row, target } of resolvedActuals) {
  if (!target) continue;        // ← unmatched rows never reach a category
```

Production for an item with **no plan entry** has no category by construction. It is recorded in `needsReview` and surfaced as the banner you already ship: *"213 produced item(s) have no matching plan entry — excluded from category totals."*

So the 201,637 PTMT August pieces are not a newly-discovered bug. **They are the documented out-of-plan quantity**, and the guard has turned a known, reported condition into a thrown exception.

Consequence: `buildPlantBundle` now throws for any month with out-of-plan production — which is every month. The PTMT plant dashboard will 500 rather than render. That is worse than the bug this commit fixed.

The distinction I should have drawn more sharply in Prompt 2: **throw when the invariant must hold; report when the gap is real and expected.**

| Guard | Invariant | Correct behaviour |
|---|---|---|
| loaded vs counted | must always hold — every loaded row belongs to a day | **throw** ✅ as implemented |
| category vs plant | cannot hold — out-of-plan rows have no category | **report**, not throw |

**Fix:** make the category check account for the unattributed quantity, then assert the completed identity.

```typescript
const categoryProducedTotal = [...categoryMap.values()].reduce((sum, d) => sum + d.produced, 0);
const unattributed = plantProduced - categoryProducedTotal;

// Every pc is either in a category or explicitly unattributed — never silently lost.
if (unattributed < 0) {
  throw new Error(`plant-engine: category total exceeds plant total by ${Math.round(-unattributed)} pcs for ${month}`);
}
if (unattributed > 0) {
  caveats.push(
    `${Math.round(unattributed).toLocaleString()} pcs produced with no matching plan entry — excluded from category totals`
  );
}
```

Return `unattributed` on the bundle so the existing banner can quote the **quantity** as well as the item count. Right now the banner says "213 items"; it has never said "201,637 pcs". That is a materially more useful number and it's already computed.

The `unattributed < 0` case genuinely must throw — categories summing to more than the plant total would mean double-counting, which is a real invariant violation.
