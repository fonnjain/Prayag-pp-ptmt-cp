# Replit Prompt — Diagnose the 19 Plan-Layer Drift Failures BEFORE Touching Any Golden

The suite is at **306/325** with 19 failing plan-layer checks, all showing category totals **down** 0.3–1.75%. The engine is almost certainly fine — every reconciliation invariant still passes, and the downstream effects chain correctly (CPVC Fitting drops → its kg drops proportionally → its W3 items shift to W4). So the **calculation is sound; the inputs moved.**

**The critical question is WHY the inputs moved, and there are two very different explanations:**

1. **Legitimate** — a newer FG stock file was uploaded, or the live Google Sheet genuinely updated. → Update the goldens.
2. **Regression** — the pipeline is now reading *less* data than before (truncated upload, dropped tab, partial sync). → The goldens are correct and the ingestion is broken.

**DO NOT update PLUMBING_GOLDEN yet.** Updating goldens to match live values would silently launder a data-loss bug into the new "correct" baseline. We have already been burned this session by plans reading less than they should (the empty-plan regression and the Combined-vs-NEW BOM gap). Diagnose first.

**The warning sign:** the drop is **broad and one-directional** — six categories all down, none up. A genuine stock/pending update usually moves items in *both* directions (some need more, some less). A uniform ~0.5–1% shrink across the board looks more like *fewer rows being read* than genuine demand shifts.
