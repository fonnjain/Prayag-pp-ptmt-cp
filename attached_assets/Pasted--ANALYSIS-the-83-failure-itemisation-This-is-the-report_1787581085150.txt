## The four unexplained gaps — I think I can identify the cause

| Category | Plan | Weekly sum | Gap |
|---|--:|--:|--:|
| CPVC Fitting | 1,042,699 | 1,042,430 | **269** |
| UPVC Fitting | 817,895 | 817,788 | **107** |
| SWR Pipe | 80,897 | 80,856 | **41** |
| AGRI Fitting | 58,712 | 58,544 | **168** |
| | | | **585** |

Not rounding — these are whole pieces, and 269 is far too large for accumulated rounding across a category.

`calc.ts:122–133`, `annotateWeeklyRelease`:

```typescript
for (const item of items) {
  if (item.maxProduction <= 0 || item.cover === "OS") continue;    // ← skipped entirely
  const band = bandsByCategory.get(item.category);
  if (!band) continue;                                             // ← skipped entirely

  const c = item.cover as number;
  let week: 1|2|3|4|null = null;
  if (c < band.w1Upper) week = 1;
  else if (c < band.w2Upper) week = 2;
  else if (c < band.w3Upper) week = 3;
  else if (c < band.w4Upper) week = 4;                             // ← may stay null
  item.week = week;
```

**Four ways an item's `maxProduction` lands in the category total but in no week:**

1. `cover === "OS"` — out of stock, so `avg3MoSale = 0` and cover cannot be computed
2. no band configured for the category
3. `cover ≥ w4Upper` — falls past every band, `week` stays `null`
4. `maxProduction <= 0` — not relevant here, since these gaps are positive

**Cause 1 is almost certainly it, and the pending fix is what exposed it.** An item with no recent sales has `cover = "OS"`. Before this change its `maxProduction` was `(buffer − stock) + 0 + 0`, which for a no-sales item is typically 0 — so it never appeared. **Now it carries pending orders**, so `maxProduction > 0` while `cover` is still `"OS"` — it enters the category total and is skipped by the weekly split.

That reads as a genuine business case: *a customer has ordered an item we have not sold in three months.* Real demand, no sales history, so no cover band.

**These four are therefore pending-driven after all** — but not as stale goldens. They are a **real defect the pending fix uncovered**: production planned at category level that never reaches a week.

### To confirm, and it is one query

For each of the four categories, list items where `maxProduction > 0` and `week === null`, with their `cover` value and `maxProduction`. The sum should equal the gap exactly — 269, 107, 41, 168.

Then decide where they belong. **W1 is the defensible default** — an open order with no sales history is unfulfilled demand and should be scheduled first, not last. But that is a business call, and whatever is chosen must be explicit rather than a silent fallthrough.

**Note the same hazard exists for causes 2 and 3.** `cover ≥ w4Upper` also leaves `week` null. Once fixed, the invariant should be `Σ(w1..w4) === maxProduction` **per item**, asserted, so no item can carry a plan quantity into no week again.
