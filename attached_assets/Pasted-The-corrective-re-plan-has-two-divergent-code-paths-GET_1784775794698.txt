The corrective re-plan has two divergent code paths — GET /plan/corrective-replan (Path A, Sheet3-based, used by the regression tests) and POST /corrective/replan (Path B, the engine behind the UI "Re-plan now" button). Path A is largely correct; Path B is broken. The regression suite validates Path A while users run Path B. Fix Path B and eliminate the divergence.

PRIORITY 1 — Plumbing production is never read (Path B). fetchDailyActuals() reads only the PTMT ANUJ sheet, so producedToDate = 0 for all 1,120 Plumbing items. Make it read Sheet3 for Plumbing (Date · Code · Qty), exactly as Path A does. Today Path A correctly reports 810,239 pcs produced; Path B reports 0.

PRIORITY 2 — Plumbing machine/category capacity is all zeros (Path B). Every Plumbing row in categoryCapacityTable has suggestedCapacity = 0, overrideCapacity = null, isThinData = 1, so catWeekCap = 0 and every item spills to unfulfillable (1,437,298 = 100% of plan). Seed the Plumbing capacities from the p90 of demonstrated daily output from Sheet3, the same calculation Path A uses. Current correct values: CPVC Fitting 34,338 · CPVC Pipe 4,960 · UPVC Fitting 20,126 · UPVC Pipe 9,875 · SWR Fitting 11,510 · SWR Pipe 2,405 · SWR Solvent 300 · AGRI Fitting 5,950 · AGRI Pipe 790. Categories with genuinely no production (CPVC/UPVC/AGRI Solvent) keep capacity 0 but must be flagged NO_DEMONSTRATED_CAPACITY, not treated as ordinary unfulfillable.

PRIORITY 3 — SWR/AGRI use the inverted formula in Path B. The engine computes max(stockNow + pendingNow − bufferReqRev + pendingLastMonth, 0) for SWR/AGRI. This is the old bug already corrected elsewhere. All materials must use the single standard rule: planRev = max((Buffer − Stock) + Pending Order + Pending Order Last Month, 0), with Stock and Buffer located by header name. Remove the SWR/AGRI special case.

PRIORITY 4 — Code normalisation missing in Path B. normalizeCode() only trims and uppercases. Use the same normalizeCodeStrict() as Path A (uppercase, strip hyphens, spaces, dots) so "A465" matches "A-465". Report unmatched production as UNMAPPED rather than dropping it.

PRIORITY 5 — asOfDate and weekClosed must agree. In weekClosed mode actuals are used unfiltered, so it doesn't equal "as of the last day of that week". Make weekClosed = N internally resolve to asOfDate = last day of week N and run the identical path. Then the consistency assertion (as-of end-of-W1 ≡ W1-closed) will hold.

PRIORITY 6 — Add kg to the corrective output. Neither result type nor the Excel export carries kg. Add kg (= pieces × BOM weight-per-piece) per item, per category, and in the export, matching the plan view's dual-unit treatment.

PRIORITY 7 — Category-level variance attribution. Item-level deltas exist but there's no per-category split of production shortfall vs new demand vs capacity infeasibility in the API response or export. Add it.

STRUCTURAL FIX (most important). Once Path B is corrected, collapse the two paths into one shared engine used by both the UI and the tests — or, at minimum, point every regression assertion at the endpoint the UI actually calls. A green suite must mean the button works. Add an assertion that the two endpoints return identical results for the same inputs, so they can never silently diverge again.

Then re-run and report per category: plan, produced, remaining, capacity/day, feasible, shortfall — from the UI path — using the actual working days remaining (not a hardcoded 15). As of 23-Jul that is 7 days, giving feasible ≈ 631,778 and shortfall ≈ 659,315.
