## 1. Fix the segment-casing silent zero (hardening)

You found that `POST /plan/runs` with `segment: "PLUMBING"` silently produced **0 items**, while `"Plumbing"` produced all 1,120.

A POST that quietly creates an **empty plan run** on a casing mismatch is the same silent-zero class that has caused the most damage in this project (`Closing Stock`, `Qty.`, `Cap/Day = 0`). It is indistinguishable from a legitimate empty result — and an empty run could then be cited as a corrective baseline, poisoning everything downstream.

**Do:**
- Normalise segment casing on `POST /plan/runs` the way `GET /plan` already does, **or** reject an unrecognised segment with a named 400 error.
- Never allow a zero-item plan run to be created silently.
- **Assertion:** creating a plan run with a valid segment in any casing yields the expected item count (PTMT 3,636 / Plumbing 1,120); an unrecognised segment fails loudly.
